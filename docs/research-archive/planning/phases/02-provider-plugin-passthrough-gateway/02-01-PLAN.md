<task type="auto">
  <name>Task 2: The atomic runtime-file contract</name>
  <files>src/hermes_auto/state/runtime.py, tests/unit/test_runtime_file.py</files>
  <action>
Read `02-CONTEXT.md` § Supervision Contract in full before writing. This file is the primitive that makes supervision immune to PID reuse, and it ships to users' disks.

Create `state/runtime.py` exporting `RuntimeFile` (frozen dataclass: `pid: int`, `port: int`, `instance_id: str`, `started_at: str`, `exe: str`), `new_instance_id()`, `write_runtime(rf)`, `read_runtime()`, `clear_runtime()`, and `RuntimeFileError`.

Three properties matter more than the code:

1. **Atomic write.** Serialize to a temp file in the same directory, `flush()` + `os.fsync()`, then `os.replace()` onto the final path. A partially-written runtime file read by a concurrent `status` is the failure this prevents. `os.replace` is atomic on both POSIX and Windows; a plain `open(...,'w')` is not.

2. **`instance_id` is fresh per process start** — `secrets.token_hex(16)`. This is what defeats PID reuse: `status` compares the `instance_id` returned by `/healthz` against the file, so a recycled PID belonging to an unrelated process cannot masquerade as a live gateway. Document that reasoning in the module docstring; the next reader will otherwise think the PID is the identity.

3. **Absent and corrupt are different states.** `read_runtime()` returns `None` when the file does not exist ("not started") and raises `RuntimeFileError` when it exists but does not parse or is missing a required field ("something is wrong"). Collapsing these into `None` would make `status` silently report "stopped" for a corrupted install.

Do not write liveness checking here — no `os.kill(pid, 0)`, no process scanning. Liveness is a `/healthz` question and belongs to plan 02-07. This module is storage only.

Tests: round-trip; `read_runtime()` on a missing file returns `None`; on a truncated file raises `RuntimeFileError`; on valid JSON missing `instance_id` raises `RuntimeFileError`; two `new_instance_id()` calls differ; `clear_runtime()` is idempotent; the temp file does not survive a successful write; a simulated crash mid-write (write temp, do not replace) leaves the previous file intact and readable.

<task type="auto">
  <name>Task 3: Token minting, cross-platform permissions, constant-time comparison</name>
  <files>src/hermes_auto/gateway/auth.py, tests/unit/test_auth_token.py</files>
  <action>
Read `docs/threat-model.md` rows 3 and 4 — they name `gateway/auth.py` as the owning module for "local port accessed by another process" and "secret leakage in logs".

Create `gateway/auth.py` exporting `mint_token()`, `read_token()`, `compare_token(supplied, expected)`, `token_permissions_ok()`, and `AuthError`.

- `mint_token()` generates `secrets.token_urlsafe(32)` and writes it to `token_path()`. POSIX: `os.open(path, O_CREAT|O_WRONLY|O_TRUNC, 0o600)` — set the mode **at creation**, not with a later `chmod`, so there is no window where the file exists world-readable. Windows: write, then `icacls <path> /inheritance:r /grant:r "<current user>":F`.
- `compare_token` uses `hmac.compare_digest`. A plain `==` short-circuits on the first differing byte and leaks length and prefix through timing. This is a one-line difference that a reviewer will not catch by reading, so a verification command asserts `compare_digest` appears in the source.
- `token_permissions_ok() -> tuple[bool, str]` **reads the effective permission back**. POSIX: `stat` and assert mode `0o600`. Windows: run `icacls <path>` and parse the output, confirming no `Everyone`/`Users`/`BUILTIN` grant. `os.chmod` does not affect Windows ACLs at all — a `0o600` call there silently leaves the token world-readable, which is exactly the defect this readback exists to catch. Return `(False, reason)` rather than raising if `icacls` is unavailable.
- Never log the token. Not at debug, not truncated, not hashed-and-logged. If you add any logging to this module, log the *path* and the *result*, never the value.

Tests: a minted token is 32+ chars and URL-safe; two mints differ; `read_token()` on a missing file returns `None`; `compare_token` returns True for equal and False for differing, including for a correct-prefix-wrong-suffix pair; `token_permissions_ok()` returns True immediately after `mint_token()` on this platform; a source scan asserts no logging call in this module takes the token value as an argument.
