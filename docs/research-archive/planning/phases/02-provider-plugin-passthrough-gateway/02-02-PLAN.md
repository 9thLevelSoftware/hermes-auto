<task type="auto">
  <name>Task 3: Redaction sink with per-install salt</name>
  <files>src/hermes_auto/telemetry/redaction.py, tests/unit/test_redaction.py</files>
  <action>
Read `docs/privacy.md` — specifically the passage stating that salting is a write-path invariant with **no Phase 1 structural backstop**, and naming where it will be enforced. You are building that backstop, one phase earlier than the document expects, because the gateway receives `root_session_id` in the `_hermes_auto` envelope from the very first request and must never log it raw.

Create `telemetry/redaction.py` exporting `install_salt()`, `session_digest(session_id)`, `redact(event)`, `get_logger(name)`, and `RedactionError`.

- `install_salt()` generates `secrets.token_bytes(32)` on first use, stores it under the state dir with the same permission treatment as the token (mode at creation on POSIX, `icacls` on Windows), and returns it. If it cannot be created, raise `RedactionError`. **Never fall back to an unsalted digest** — a silent fallback defeats exactly the guarantee this module exists to provide, and would do so invisibly.
- `session_digest(session_id)` returns `hmac.new(salt, session_id.encode(), 'sha256').hexdigest()` — 64 lowercase hex, matching the `^[0-9a-f]{64}$` pattern Phase 1 froze on `root_session_hash` in both routing schemas. Use HMAC, not `sha256(salt + id)`, so length-extension is not even a question a reviewer has to ask.
- `redact(event)` returns a new dict with banned keys **dropped** and a `_redacted` list naming what was dropped. Banned: `messages`, `content`, `prompt`, `tool_calls`, `tool_result`, `tool_output`, `arguments`, `authorization`, `api_key`, `token`, `secret`. Recurse into nested dicts and lists. Any key named `root_session_id` or `session_id` is replaced by `root_session_hash` carrying the digest.
- `redact()` must **never raise** on unexpected input. A logging path that raises converts an observability call into an outage. Unknown types pass through as `repr()`-truncated to 64 chars.
- `redact()` is idempotent — redacting twice equals redacting once.
- `get_logger(name)` returns a logger whose formatter routes every record through `redact()`.

Tests: a digest is 64 lowercase hex and matches the frozen pattern; **two different salts over the same session id produce different digests** — this is the property the privacy guide promises; the same salt is stable across calls; each banned key is dropped and named in `_redacted`; nested and list-nested banned keys are dropped; `redact()` is idempotent; `redact()` does not raise on a non-dict, a cyclic-ish structure, or a bytes value; a log record built from a realistic `_hermes_auto` envelope contains the digest and **not** the raw session id; the salt file's permissions pass the same readback used for the token.
