<objective>
Define the four versioned JSON Schemas that describe the router's own evidence records: the `_hermes_auto` request envelope, the `RouteDecision` explainability record, the candidate model card, and the telemetry outcome event.

Purpose: these are the contracts that Phases 3, 4, and 8 implement against. Freezing them now — before any routing code exists — is what makes the Phase 1 exit criterion "schemas are versioned" meaningful. The outcome-event schema in particular encodes the privacy posture structurally, so a later phase cannot accidentally start storing prompts and still pass validation.
Output: `src/hermes_auto/data/schema/routing/` with four versioned schemas, plus contract tests with positive and negative fixtures including privacy-invariant tests.
</objective>

**`hermes-auto-metadata.v1.schema.json`** — the envelope the provider plugin injects via `build_extra_body()` and the gateway strips before forwarding upstream.

Required: `protocol_version` (integer, const 1), `root_session_id` (string, minLength 1), `virtual_model` (string), `plugin_version` (string).

Optional: `auxiliary_task` (string, nullable) — the auxiliary task alias when the call comes from a configured auxiliary entry per design.md §8.3.

Set `"additionalProperties": false`. This envelope is fully controlled by the provider plugin, so unknown keys indicate a version mismatch and should fail loudly rather than pass silently.

The `description` must state two things: the gateway MUST strip this key before sending the request upstream (design.md §5.1), and a `protocol_version` other than 1 must be rejected rather than best-effort parsed.

**`route-decision.v1.schema.json`** — the explainability record every route produces.

Required: `decision_id` (string, pattern `^dec_`), `root_session_hash` (string — hashed, never the raw id), `lane_id` (string), `cache_epoch` (integer, minimum 0), `turn_id` (integer, minimum 0), `mode` (enum `quality`, `balanced`, `economy`, `session`), `requirements` (object), `excluded` (array), `ranked` (array), `selected` (string or null), `reason_codes` (array).

`requirements` is an object whose properties are the eight capability dimension names from design.md §7.2, each `{"type": "number", "minimum": 0, "maximum": 1}`, with `"additionalProperties": false`. Not all eight need be present in a given record, so do not mark them required — a heuristic predictor may emit a subset.

`excluded` is an array of objects, each requiring `candidate` (string) and `reasons` (array of strings, minItems 1). Making `reasons` non-empty is what enforces the phase criterion that every excluded candidate carries a machine-readable reason.

`ranked` is an array of objects, each requiring `candidate` (string), `shortfall` (number, minimum 0), `final_loss` (number). Optional per-entry: `estimated_cost` (number or null, minimum 0), `estimated_ttft_ms` (integer or null, minimum 0), `health` (number 0–1), `switch_penalty` (number, minimum 0). Note that `shortfall` has a minimum of 0 and no maximum, because it is a sum of positive deficits across weighted dimensions.

`selected` is `["string", "null"]` — null represents a structured failure where no hard-eligible candidate remained.

`reason_codes` is an array whose items are an enum containing exactly these twelve values from design.md §12: `HARD_REQUIREMENT`, `CAPABILITY_FIT`, `DOMAIN_AFFINITY`, `COST_TIEBREAK`, `LATENCY_TIEBREAK`, `STICKY_CACHE`, `SWITCH_HYSTERESIS`, `USER_PIN`, `HEALTH_VETO`, `PROVIDER_FALLBACK`, `CONTEXT_ANCHOR`, `EMERGENCY_DEFAULT`. Count them — there must be exactly twelve.

Optional top-level: `model_card_version` (string) and `router_version` (string), so a decision is replayable against the exact card snapshot that produced it, per the Phase 3 criterion.

Set `"additionalProperties": false`.

The `description` must state that this record is derived only from router inputs, scores, and policy, and never from hidden model reasoning (design.md §12).

Explicitly do NOT add: raw prompt text, message content, tool arguments, tool results, or any credential value. Do not add a field that would let a caller round-trip the request body.

Read `design.md` §9.2 for the model-card example, §7.2 for the capability and domain vocabularies, §13.1 through §13.3 for telemetry, and `docs/adr/0003-model-card-architecture.md` for the candidate-identity and precedence decisions.

**`model-card.v1.schema.json`**

Required top-level: `id` (string, minLength 1), `enabled` (boolean), `transport` (object), `capabilities` (object), `limits` (object).

`transport` requires `adapter` (string), `provider` (string), `model` (string); optional `base_url` (string, format uri) and `credential_ref` (string, pattern `^(env:[A-Z0-9_]+|none)$`). That pattern is deliberate: it permits only an environment-variable reference or the literal `none`, so a raw key can never be written into a card and pass validation.

`capabilities` requires all eight dimension names from design.md §7.2, each `{"type": "number", "minimum": 0, "maximum": 1}`, with `"additionalProperties": false`. All eight are required here — unlike the requirement vector, a card must be complete, because a missing dimension would silently score as a surplus.

`affinities` (optional object): domain tag names as properties, each a number 0–1. Use the ten domain tags from design.md §7.2: `frontend_ui`, `backend_application`, `systems_infrastructure`, `database_sql`, `security`, `research`, `writing`, `mathematics`, `data_analysis`, `local_machine_operations`. Set `additionalProperties: false` so a typo in a domain name fails rather than silently scoring zero.

`limits` requires `context_tokens` (integer, minimum 1), `max_output_tokens` (integer, minimum 1), `tools` (boolean), `vision` (boolean), `structured_output` (boolean).

`economics` (optional object) with `input_per_million`, `output_per_million`, `cache_read_per_million`, `cache_write_per_million`, each `{"type": ["number", "null"], "minimum": 0}`. The object description must state: null means unknown pricing; unknown is never treated as zero; per design.md §7.5 an unknown-priced candidate is excluded from `economy` mode by default and allowed in `quality` only when the user permits it.

`harness` (optional object) with `profile` (string), `version` (integer, minimum 1), `reasoning_policy` (string), `cache_strategy` (string). ADR-0003 makes harness version part of candidate identity, so `version` is an integer that must increment, not a free-form string.

`policy` (optional object) with `privacy_class` (enum `cloud`, `approved`, `local`), `experimental` (boolean), `allowed_modes` (array of the mode enum).

`evidence` (optional object) with `source_version` (string), `calibration_dataset` (string), `sample_count` (integer, minimum 0).

`context_anchor` (optional boolean, default false) — flags a candidate that must support the advertised virtual context window per design.md §9.4.

Set `"additionalProperties": false` at top level.

**`outcome-event.v1.schema.json`**

This schema is where the privacy posture becomes structural. Required: `event_id` (string), `event_type` (enum), `occurred_at` (string, format date-time), `root_session_hash` (string), `lane_id` (string).

`event_type` enum: `request_completed`, `request_failed`, `turn_completed`, `tool_error`, `user_feedback`, `health_observation`, `fallback_used`.

Optional numeric and categorical fields only, drawn from design.md §13.2 and §13.3: `decision_id` (string), `candidate` (string), `ttft_ms` (integer, minimum 0), `total_latency_ms` (integer, minimum 0), `input_tokens`, `output_tokens`, `cached_tokens`, `reasoning_tokens` (integers, minimum 0), `actual_cost_usd` (number or null, minimum 0), `tool_call_count`, `invalid_tool_call_count`, `retry_count` (integers, minimum 0), `empty_response` (boolean), `context_compressed` (boolean), `user_interrupted` (boolean), `turn_succeeded` (boolean), `feedback` (enum `good`, `bad`), `error_class` (string — a classification like `rate_limit` or `auth_failure`, never a raw error body).

Set `"additionalProperties": false` at every object level in this schema.

The `description` must state the four prohibitions from ADR-0004 and design.md §13.1: no raw prompt text, no tool-result bodies, no secrets, and root session identifiers are hashed with a local salt.

Do NOT add any of these properties under any name or spelling: `prompt`, `prompt_text`, `raw_prompt`, `messages`, `content`, `tool_result`, `tool_output`, `response_text`, `api_key`, `secret`, `credential`. The verification command greps for several of these; adding one fails the plan.
