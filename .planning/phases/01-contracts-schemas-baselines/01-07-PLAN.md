<objective>
Build the fixed-model baseline corpus and the measurement harness that turns recorded runs into a reproducible report covering quality, cost, latency, cache, and tool-call metrics — plus the evaluation methodology document that explains how the numbers are produced.

Purpose: design.md §18 Phase 0 requires assembling a representative fixed-model baseline corpus and establishing current quality, cost, latency, cache, and tool-call baselines, with the exit criterion "baseline tasks run reproducibly." Every later claim the project makes — the 20% `balanced` cost reduction gate, the quality non-inferiority gate, Phase 8's router-benefit measurement — is measured against this baseline. If it is not reproducible now, none of those claims are checkable later.
Output: `src/hermes_auto/evaluation/` with corpus, metrics, and baseline modules; `scripts/benchmark.py`; the corpus and recorded-run fixtures; a determinism test; and `docs/evaluation.md`.
</objective>

Edge/error cases:
- Duplicate `task_id` in the corpus raises `CorpusError` naming the id.
- A recorded run referencing a `task_id` absent from the corpus raises `CorpusError` naming both.
- An empty runs list produces a report with zero counts rather than raising — an empty baseline is a valid, reportable state.
- Percentile computation on a single sample must return that sample, not raise or return None.
- Cost aggregation must treat a `null` `actual_cost_usd` as unknown and report it in a separate `unknown_cost_count`, never as zero. This mirrors the design.md §7.5 rule and is the single most important correctness property in this plan.
- **No aggregate field may ever be `nan` or `inf`.** When `distinct_task_count == 0`, `success_rate` and `mean_tool_calls_per_task` are `0.0`. When `succeeded_count == 0`, `mean_cost_per_succeeded_task` is `0.0`. When `total_input_tokens == 0`, `cached_token_ratio` is `0.0`. A zero-success group is *reachable* — the fixtures are required to contain a `turn_succeeded: false` event — so these are live code paths, not theoretical ones. `f"{float('nan'):.6f}"` renders `nan`, which silently defeats byte-comparison.
- **`generated_from` holds basenames only** — never absolute or relative paths, which would make rendered output depend on the working directory and defeat the reproducibility contract. `BaselineReport` contains no timestamp, hostname, platform, package-version, or random field of any kind.
- Float formatting in output must be fixed-precision (`f"{value:.6f}"`, never `str()`) so two runs produce byte-identical text.

**Field naming — resolve the collision.** `MetricSummary` uses `event_count` (number of events aggregated) and `distinct_task_count` (number of unique `task_id` values), never a bare `task_count`. `BaselineReport.task_count` is `len(corpus)`. **`metrics.py`.** Export `MetricSummary` (frozen dataclass) and `aggregate(runs: list[dict]) -> MetricSummary`. Read metric fields from `entry["event"]` and the join key from `entry["task_id"]`.

`MetricSummary` fields, covering the five dimensions design.md §18 Phase 0 requires:
- Quality: `event_count`, `distinct_task_count`, `succeeded_count`, `success_rate`, `invalid_tool_call_count`, `empty_response_count`.
- Economics: `total_cost_usd` (sum of known costs only), `known_cost_count`, `unknown_cost_count`, `mean_cost_per_succeeded_task`.

`aggregate` rules:
- Never treat `null` `actual_cost_usd` as zero. Sum only known values into `total_cost_usd` and count the rest into `unknown_cost_count`. This is the single most important correctness property here.
- Compute percentiles with `statistics.quantiles` or an explicit nearest-rank implementation. On a single sample, return that sample. On an empty list, return `0.0`.
- Round every float field to 6 decimal places before storing, so repeated runs produce identical output.
- Return a zero-valued summary for an empty runs list rather than raising.
- **Guard every division.** `success_rate` and `mean_tool_calls_per_task` divide by `distinct_task_count`; `mean_cost_per_succeeded_task` divides by `succeeded_count`; `cached_token_ratio` divides by `total_input_tokens`.
