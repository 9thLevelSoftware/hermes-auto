<objective>
Build the gateway request path: a Starlette ASGI app that authenticates, strips the `_hermes_auto` envelope, forwards an otherwise-untouched body to one configured upstream, and relays the SSE response byte-for-byte.

Purpose: this is R3 and R5. The design commitment is that the response path never parses upstream bytes, so "identical behavior" holds by construction rather than by diligence.
Output: six `gateway/` modules, `health/probe.py`, a passthrough contract suite, and the validation-cost measurement that decides a config default.
</objective>

- `upstream.py` — `UpstreamClient` wrapping one `httpx.AsyncClient`, exposing `async stream(body, headers) -> tuple[int, httpx.Headers, AsyncIterator[bytes]]` and `async complete(body, headers)`. **Returning bytes alone is insufficient** — this plan's own edge cases require relaying upstream status and headers unchanged, and an async generator cannot hand back headers before its first yield. Declare the hop-by-hop drop set as a module constant: `connection`, `keep-alive`, `transfer-encoding`, `upgrade`, `proxy-authenticate`, `proxy-authorization`, `te`, `trailer`. - `ingress.py` — `authenticate(request)`, `enforce_limits(request)`, `strip_envelope(body) -> tuple[dict, dict]` returning `(forwarded_body, hermes_auto_envelope)`.
- `relay.py` — `async relay_stream(upstream_iter) -> AsyncIterator[bytes]`, pure byte passthrough.
- `app.py` — `create_app(config=None) -> Starlette` with the four routes.
- `main.py` — `__main__` entry that binds, writes the runtime file **after** the bind, and serves via uvicorn.
Edge/error cases:
- Missing or wrong bearer token → 401 in the `openai-error.v1` shape, with **no** timing difference between "no token" and "wrong token" beyond `compare_digest`.
- Body over the size cap → 413 before any upstream connection is opened.
- Upstream connection refused → 502 in the error shape; the client must not see a truncated 200.
- Upstream returns a non-2xx → status, headers, and body relayed through unchanged. The gateway does not reinterpret provider errors.
- Client disconnects mid-stream → the upstream request is cancelled, not left dangling. Use `asyncio` cancellation, and assert it in a test.
- Hop-by-hop headers (`connection`, `keep-alive`, `transfer-encoding`, `upgrade`) are not copied in either direction.

<task type="auto">
  <name>Task 2: Ingress and the byte-transparent relay</name>
  <files>src/hermes_auto/gateway/ingress.py, src/hermes_auto/gateway/relay.py</files>
  <action>
`ingress.py`:
- `authenticate(request)` — bearer token via `compare_token` from `gateway/auth.py`. Reject with 401 in the error envelope. Do not branch differently for "absent" versus "wrong"; both go through the same comparison path.
- `enforce_limits(request)` — content-type must be JSON; body size cap (default 32 MiB, config-overridable); 413 before opening any upstream connection.
- `strip_envelope(body) -> (forwarded_body, envelope)` — `json.loads` once, `pop("_hermes_auto")`, return both. The forwarded body is re-dumped with `json.dumps(..., separators=(',',':'), ensure_ascii=False)`. **Every other field passes through untouched**, because nothing is modeled — this is what makes R5 hold for fields we have never heard of.
- Validate the popped envelope with a **hoisted** `build_validator` against `hermes-auto-metadata.v1`. It is our object, about five fields, microseconds. A `protocol_version` other than 1 is rejected with 400 — the envelope schema says so and Phase 1 wired the `$ref` to enforce it.
- Full `openai-chat-request.v1` validation runs **only** when `config.gateway.strict_validation` is true, using a validator hoisted at startup. Default is off per `02-CONTEXT.md` § Request Validation Policy.

`relay.py`: `async relay_stream(upstream_iter)` yields bytes unchanged. No decoding, no line splitting, no re-framing, no buffering beyond what the transport requires. Add a docstring stating that this function deliberately does not understand SSE, and that any future change which parses here must justify itself against R5.

Leave a named, empty extension point for the §8.2 first-chunk commit barrier — a comment and a clearly-marked place, not an abstraction. Phase 6 attaches there.

`app.py` — `create_app(config=None) -> Starlette` with routes `POST /v1/chat/completions`, `GET /v1/models`, `GET /healthz`, `GET /readyz`. Build every validator and the `UpstreamClient` in a startup handler; close the client on shutdown. All logging via `get_logger` from `telemetry/redaction.py`.
- `/v1/models` returns the four virtual model ids (`auto:quality|balanced|economy|session`) in OpenAI list shape. It does **not** proxy upstream — Hermes asks this to populate its picker.
- `/healthz` is liveness: returns `{"status":"ok","instance_id":...}` reading `instance_id` from the runtime file. **The `instance_id` echo is what makes supervision immune to PID reuse** — plan 02-07 compares it. Do not omit it.
- `/readyz` is readiness: attempts a cheap upstream reachability check, returns 200 or 503 with a reason. Health and readiness are different questions; do not alias them.

`health/probe.py` — the reachability check `/readyz` calls, kept separate so Phase 6 can extend it without touching the app.

`main.py` — bind the **inference** socket and the **admin** socket (from `hermes_auto.gateway.admin.create_admin_app`, plan 02-06) on one asyncio loop in one process, then write the runtime file with both `port` and `admin_port` **after both binds succeed**, then serve. `admin_main.py` is debug-only and nothing supervises it. This matters because plan 02-07's `stop()` POSTs to `/admin/v1/shutdown` as its primary path on every platform — an admin listener that no supervised process starts makes graceful drain unreachable and silently degrades every stop to a hard kill. Import `create_admin_app` lazily so this plan does not block on 02-06 landing; if it is absent at runtime, log and serve inference only. Writing before the bind is the race that makes `status` report a live gateway that never came up. Bind `127.0.0.1` only; a config value that is not a loopback address is a startup error, not a warning.

`tests/contract/test_passthrough_identity.py` — drive `MockUpstream` from plan 02-03:
- Each of the 12 fixtures relayed through the gateway yields bytes identical to the direct-from-mock bytes, after normalizing only `id` and `created`

- Missing token → 401; wrong token → 401; both in the error envelope
- Oversized body → 413, and `.requests` is empty (no upstream connection was opened)
- Upstream 429 and 400 are relayed with status and body intact
- Client disconnect mid-stream cancels the upstream request
- Hop-by-hop headers are not forwarded

`tests/performance/test_validation_cost.py` — **measure, do not assume.** Time a hoisted `openai-chat-request.v1` validator against a realistic 100–200 KB `messages` body over at least 200 iterations.
