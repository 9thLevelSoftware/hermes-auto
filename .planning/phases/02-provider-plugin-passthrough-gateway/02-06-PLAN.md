Purpose: `design.md` §5.3 requires the admin API on a different authentication scope and preferably a separate listener. Phase 1's threat model explicitly recorded that **no §21 row covers admin-scope privilege separation** and assigned it here. `/admin/v1/shutdown` is also the primary stop path plan 02-07 depends on.
Output: `gateway/admin.py`, `gateway/admin_main.py`, and the admin contract suite.
</objective>

<task type="auto">
  <name>Task 1: A distinct admin token scope</name>
  <files>src/hermes_auto/gateway/admin.py (token portion)</files>
  <action>
Add to `admin.py`: `ADMIN_TOKEN_FILENAME = "admin-token"`, `mint_admin_token()`, `read_admin_token()`, and `require_admin(request)`.

The admin token is a **separate secret in a separate file** under the state dir, minted with the same permission treatment `gateway/auth.py` uses (mode at creation on POSIX, `icacls` on Windows). Reuse `compare_token` from `gateway/auth.py` — do not reimplement constant-time comparison, and do not import the inference token.

The security property: possessing the inference token grants no admin capability. `/admin/v1/sessions/{id}/reroute` and `/pin` redirect every subsequent turn to an attacker-chosen candidate — an unauthorized-routing and cost-abuse primitive that bypasses the policy layer entirely. Phase 1's threat model flagged that no `design.md` §21 row covers this and assigned the mitigation here.

`require_admin` returns a 401 error-envelope response on failure and never reveals which token was expected.

<task type="auto">
  <name>Task 2: Admin routes, with honest 501s for routing that does not exist</name>
  <files>src/hermes_auto/gateway/admin.py (routes)</files>
  <action>
`create_admin_app(config=None) -> Starlette` with these routes, all behind `require_admin`:

**Implemented:**
- `GET /admin/v1/status` — `{instance_id, pid, port, started_at, uptime_seconds, upstream_base_url, strict_validation}`. Read `instance_id` from the runtime file. **Never** include the inference token, the admin token, or the resolved upstream credential — route the payload through `redact()` from plan 02-02 as a second barrier.
- `POST /admin/v1/shutdown` — 202, then a graceful drain. In-flight streams complete; new requests are refused. This is the **primary stop path on every platform**, because Windows has no `SIGTERM` and plan 02-07's supervisor depends on it.

**Not implemented — return 501:**
- `GET /admin/v1/decisions/{decision_id}` — needs `RouteDecision` records, Phase 4
- `POST /admin/v1/sessions/{session_id}/reroute` — needs cache epochs, Phase 5
- `POST /admin/v1/sessions/{session_id}/pin` — needs candidate inventory, Phase 3
- `POST /admin/v1/feedback` — needs the telemetry store, Phase 8

Each 501 body uses the `openai-error.v1` shape with `type: "not_implemented"` and a message naming the phase that delivers it. A stub returning a fabricated success would be worse than a 501 — it would let a caller build against behavior that does not exist.
